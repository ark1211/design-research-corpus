# [VA-001] Suggestion chips must be action verbs anchored to user intent, not topic labels

## Rule

Suggestion chips displayed in a virtual assistant must be phrased as **action verbs anchored to user intent**, not as topic labels or noun phrases. Every chip must complete the implicit user question "I want to…" — e.g., "Track my order," "Find the best laptop for me," "Get technical support." Chips that name topics ("Orders," "Laptops," "Support") without action framing must not be used as primary conversational entry points, because they force the user to guess what will happen when tapped and shift the burden of task articulation from the assistant to the user.

## Scope

**Applies to:** All virtual assistant surfaces where suggestion chips are used to bootstrap or continue conversations, across authenticated consumer, SMB, commercial, and enterprise contexts. Includes initial-state chips (shown before the user has typed anything), follow-up chips (shown as replies to VA responses), and re-engagement chips (shown when a conversation has stalled).

**Does not apply to:** Navigation chips within a canvas (which are structural, not conversational). Filter chips in a list or search UI (which modify state, not initiate intent). Category cards on a landing page (different pattern, different research). Voice-first VA surfaces where chips may not be visible.

## Evidence

Action-verb chips outperform topic-label chips on every meaningful conversational metric: task initiation rate, task completion rate, user-reported clarity, and reduction in "what does this do?" clarifying questions. The reason is cognitive: users approach a VA with an intent ("I need to renew my subscription") but often don't know how the VA has scoped its capabilities. A topic label like "Subscriptions" requires the user to hypothesize whether their intent is covered. An action-verb chip like "Renew my subscription" *confirms* it before the user commits attention.

Nielsen Norman Group's research on conversational interfaces identifies the "guess the vocabulary" problem as the single biggest source of abandonment in early conversational UIs. Users abandon not because the VA couldn't help, but because they couldn't tell whether it could help without investing effort to find out. Action-verb chips solve this: the chip *is* the vocabulary, matched to intent.

Google's People + AI Guidebook (PAIR) explicitly recommends that suggested inputs be "written as complete user intents in first-person or imperative form" — the reasoning being that this reduces the calibration burden between the user's mental model and the system's capabilities. Microsoft's HAX Toolkit converges on the same guidance under Guideline 4 ("Show contextually relevant information"): suggestions should reveal what the system can *do*, not what it can *talk about*.

There's a second, subtler benefit: action-verb chips create implicit training data. When a user taps "Track my order" and the VA fulfills that intent, the user learns that this VA is a *thing-doer*, not a chatbot. That framing carries into subsequent turns and dramatically changes how users type free-form prompts later in the session — they type actions ("Show me deals on XPS 15") rather than topics ("XPS 15?").

There's a third benefit specific to authenticated contexts: action-verb chips can incorporate account-specific state. "Track my order" implicitly means *my* order, which is only meaningful in an authenticated context. This creates a tight visual signal that the VA knows who the user is and has their context loaded — which itself is a trust signal for the moment the user first opens an authenticated VA.

The chip label should also be **short enough to scan in under one second** — ideally 3-5 words, never more than 7. Longer chips reduce scan speed and make chip rows feel like walls of text rather than choices.

## Anti-patterns

- Topic-label chips as primary entry points: "Orders," "Products," "Support"
- Noun-phrase chips that hide the action: "Order status" instead of "Track my order"
- Chips that are so long they wrap onto multiple lines
- Chips whose action is ambiguous about scope: "Deals" could mean current deals, personalized deals, or search-by-deal-price
- Chips that duplicate main-nav labels — if the site nav already has "Support," a chip labeled "Support" is redundant and confusing
- Chips that show more than 6-7 options at once (scan fatigue; users skip them entirely)
- Chips that don't reflect the authenticated context: showing "Sign in" as a chip to a user who is already signed in

## Notes

Dell's current VA implementation (as of the screenshot shared) already uses action-verb chips on the anonymous surface ("Show current deals," "Find the best laptop for me," "Track my order," "Get technical support," "Chat with sales"). This is good and should be preserved. This finding codifies *why* it works and prevents future regression toward topic-label chips.

For authenticated VA surfaces, the chip set should shift: less "Show current deals" (generic) and more "Renew my subscription that expires Nov 2" (account-specific). Personalization is a separate finding (VA-004, planned), but the action-verb form persists across both.

For chips that lead into canvas-heavy flows (subscription renewal, product configuration), the chip label should still be phrased as the user's intent ("Renew my subscription"), not the mechanism ("Open renewal builder"). Users think in intents, not tools.
